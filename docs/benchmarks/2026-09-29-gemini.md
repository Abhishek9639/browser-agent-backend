# Benchmark 2026-09-29 (gemini)

5 runs, 5 per configuration, against SkyFare on darwin.

> **Added by hand after the run: this is not a measurement of the agent.**
>
> Every one of the five runs failed with `LLMUnavailable`, because
> `gemini-3.6-flash` answered every request with
> `503 "This model is currently experiencing high traffic"`. The retry wrapper
> exhausted its attempts against that and gave up, which is the correct
> behaviour. One run executed a single step before the provider stopped
> answering; the other four executed none.
>
> So the 0% end-to-end success below is a statement about provider availability
> at 09:32 on 2026-09-29, not about the loop. Nothing was retried, per
> instruction. The headline numbers remain the mock run in
> `2026-09-28-mock.md`, which is what the section 9 targets are measured against.
>
> What this run does show, and it is worth something: a provider returning 503 on
> every call degrades to five clean failures with a readable reason and no
> crash, and the verification accuracy stayed at 100% because the one step that
> did run was checked properly.
