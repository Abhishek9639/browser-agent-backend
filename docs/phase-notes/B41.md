# B41 - Full screen, a visible pointer, and autocomplete

## What was built

A maximised browser the page fills, a pointer and smooth scrolling the person can watch, and three fixes found by running the IRCTC booking task until it stopped failing for reasons in our code.

## Key decisions

A maximised window has no configured viewport and Playwright reports none, so the size is measured from the page every time anything needs it. The alternative, a fixed size, is what made the window a small box in a big screen. The pointer is a page overlay following real mouse events rather than a drawn cursor, because Playwright moves an invisible one; before each click the real pointer glides there so the movement the person sees is the movement that happened. All of it is off in a headless run, where nobody is watching and the extra events would only cost time.

The autocomplete failure was the verifier checking the wrong thing: the planner correctly expected the field to hold the station, the verifier looked at the list item that was just clicked, and a list item is gone the moment it works. The replay failure was a state-tracking variable that did not know `_verify` had moved the task to RECOVERING; the fix reads the task's real status instead of trusting the local copy.

## Viva questions

**1. Why measure the viewport instead of configuring it?**
A maximised window has no size we chose. A wrong number silently breaks every coordinate: the screenshot maps onto the page wrongly and a vision-guided click lands elsewhere.

**2. Why glide the pointer rather than only draw it?**
An overlay that jumps to the target would show a pointer that never moved, which is a lie about what the browser did. Moving the real pointer first means the cursor on screen is the cursor that clicked.

**3. Why read the status from the record in the replay fix?**
The loop kept its own idea of the phase, and a helper it called changed the real one. Two copies of a fact drift; the record is the one the state machine enforces.
