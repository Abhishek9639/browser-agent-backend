# B35 - Run in installed Chrome, and say why an action failed

## What was built

`AGENT_BROWSER_CHANNEL` to launch the installed Chrome, a failure reason that names the cause, and planner guidance on `wait`.

## Key decisions

A task asked for `internshaala.com` (a typo copied from the instruction) and failed with only "The action did not run", which hid a DNS error. The driver already reduces Playwright's message to one line with no page content, so it is safe to put in the reason. A real end-to-end run on SkyFare in Chrome then showed a second problem: the fallback model chose `wait` on a finished page and expected the DOM to change. That is a planning error, so the prompt was fixed rather than loosening the verifier.

## Viva questions

**1. Why fix the prompt instead of making the verifier accept a no-op wait?**
A wait that changes nothing on a finished page is the model failing to notice the goal is met. Accepting it would hide that and let the loop spin.

**2. Is it safe to show Playwright's error text?**
Only the first line, capped at 200 characters, is stored. It names the action and URL, not page content, which spec section 10 forbids storing.

**3. Why channel=chrome rather than only CDP?**
It needs no debugging port or separate profile, and behaves like a normal install. CDP remains for driving a window the user already has open.
