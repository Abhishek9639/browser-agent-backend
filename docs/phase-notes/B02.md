# B02 - App core, errors, logging, health

## What was built

The cross-cutting layer every later part sits on: configuration, logging, the error contract, request correlation, and an app factory with one endpoint proving it all works.

- `app/core/config.py` - `Settings` over pydantic-settings. Six groups: app, database, JWT, LLM, agent budgets, billing, storage. Secrets are `SecretStr`, list settings take comma-separated values, `get_settings()` is `lru_cache`d.
- `app/core/logging.py` - structlog. JSON in prod, coloured console in dev. `request_id` merges in from contextvars. `redact_sensitive` is the last processor before rendering.
- `app/core/errors.py` - the `AppError` hierarchy and four handlers that all produce the spec section 6 envelope.
- `app/core/middleware.py` - `RequestContextMiddleware`: correlation id in, correlation id out, one access log line.
- `app/api/deps.py`, `app/api/v1/router.py`, `app/api/v1/health.py`, `app/main.py`.
- 49 unit tests.

## Key decisions

**Request validation returns 400, not 422.** FastAPI raises `RequestValidationError` as 422 by default, but spec section 6 assigns 400 to validation and reserves 422 for "unrecoverable action", which is an agent concept: the browser could not carry the action out. Two different failures should not share a status code, so the handler remaps to 400. The frontend team needs to know this, since it differs from stock FastAPI.

**Redaction is a processor, not a call-site discipline.** Spec section 10 bans logging page content, screenshots, credentials and typed passwords. Relying on every author to remember that is how leaks happen. `redact_sensitive` sits last in the chain, so anything any processor adds is still scrubbed, and it recurses through nested dicts, lists and tuples. Matching is a broad substring test on the key: `card` also catches `card_number` and `cardholder`. Over-redacting a log line is cosmetic, under-redacting one is an incident.

**Settings come from app state, not the module cache.** The first version of `health` called `get_settings()` directly, and a test caught it immediately: an app built with `create_app(Settings(APP_ENV=TEST))` still reported `dev`, because the handler read the cached global. `SettingsDep` reads `request.app.state.settings`, so the factory override is honoured all the way down. Without this, every later test that needs non-default configuration would have had to mutate a global.

**The catch-all handler logs the trace and returns nothing.** `unhandled_exception_handler` logs with `logger.exception` and responds with a fixed message. A test asserts the response contains neither the original exception text, nor `Traceback`, nor the exception class name.

**Exception class names keep the prompt's spelling.** ruff's N818 wants an `Error` suffix. `raise NotFound()` reads better than `raise NotFoundError()`, and the names were specified, so N818 is disabled for that one file with a comment rather than renaming.

## Viva questions

**Why is the request id worth this much machinery?**

There are three services and a browser agent in this system, and one user action can fan out across all of them: the frontend calls `POST /tasks`, the backend reserves credits against payments, then runs a 25-step agent loop, each step writing rows and pushing WebSocket events. When something fails, "which request was that?" has to be answerable from a log search. The middleware honours an inbound `X-Request-ID` so the frontend's id flows through, generates one otherwise, echoes it on the response, and binds it into contextvars so every structlog event carries it without being passed as an argument. The same id goes into the error envelope, so a user can quote the `requestId` from a failure and it finds the exact log line.

**Why does the redaction processor go last in the chain rather than first?**

Processors run in order, each free to add keys. If redaction ran first, anything added afterwards, by `TimeStamper`, by `merge_contextvars`, by an exception formatter, would be rendered unscrubbed. Putting it immediately before the renderer means the dictionary that gets serialised is the dictionary that was scrubbed. The cost is that redaction sees the most data, which is exactly the point.

**What does the app factory pattern buy over a module-level `app = FastAPI()`?**

Configurability and test isolation. `create_app(settings)` lets a test build an app with `APP_ENV=test`, a different CORS origin, or billing disabled, without touching environment variables or clearing an `lru_cache` between tests. `tests/unit/test_errors.py` builds its own app and attaches routes that raise on demand, which would otherwise mean polluting the production router with test-only endpoints. The module-level `app = create_app()` still exists at the bottom of `app/main.py`, because `uvicorn app.main:app` needs something to import.

## Follow-ups

- `GET /metrics` at the root is still unimplemented; it belongs with the Prometheus collectors.
- The lifespan hook has ordered placeholders for the database pool, the browser pool and the task runner. Startup order is db, browser, runner; shutdown is the reverse.
- Starlette 1.6 deprecates `TestClient` on httpx. The suite already uses `httpx.AsyncClient` with `ASGITransport`, so there is nothing to migrate later.
