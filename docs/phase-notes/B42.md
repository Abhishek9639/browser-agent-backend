# B42 - Typing, scrolling and login waits on any site

## What was built

Fixes for the three things that made real sites fail: text that did not land in the field, a page that scrolled something other than the window, and the task clock running while a person signed in.

## Key decisions

The IRCTC date failure was the planner pointing "Date input field" at a 26 by 26 pixel swap button. Rather than loosen the driver, the planner is now refused that target with a list of the real fields, which works on any site; the driver then copes with the widgets that remain (wrapper selectors, fields that discard a fill, key-driven widgets). Scrolling had two copies of "the page" (the window for moving, the window for measuring), so one snippet now finds what scrolls and both use it. A login wait cannot spend the task's time limit, so waiting on a person is taken out of the budget instead of the limit being raised.

## Viva questions

**1. Why refuse the planner a bad target instead of making the driver cope?**
A button cannot hold text, so no amount of driver cleverness makes the step right; it only moves the failure later. Naming the real fields fixes the cause and costs one repair turn.

**2. Why one snippet for scrolling and measuring?**
If moving and measuring disagree about what scrolls, a working scroll reads as no scroll and the verifier fails a step that worked.

**3. Why exclude the wait from the budget rather than extend the limit?**
The limit exists to stop a runaway agent. Time a person spends signing in is not the agent running away, and a longer limit would also let a stuck agent run longer.
