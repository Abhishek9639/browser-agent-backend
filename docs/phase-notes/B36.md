# B36 - Sign-in hand-off and a working indicator

## What was built

The agent no longer tries to get past a sign-in or sign-up. It pauses, hands the visible browser to the person, and continues when they confirm. While it works, each tab it uses has a blue frame and a label.

## Key decisions

The hand-off reuses the approval gate rather than adding a state or an endpoint. The state machine only allows `AWAITING_APPROVAL -> ACTING`, so the loop walks `ACTING -> VERIFYING -> PLANNING` after the person confirms. Detection is deterministic (a password field, or a login path with an email field) because "should I invent an account" is not a question for a model. A failed click that leaves a sign-in prompt behind is treated as a hand-off, not a failure, since the earlier "could not click Apply now" was the prompt covering the button. The frame is an init script so it survives navigation, and it is hidden around screenshots so it never reaches the vision model.

## Viva questions

**1. Why reuse the approval flow for sign-in?**
It already persists a pending row, survives a reconnect, times out and can be rejected. A new state would have changed the formally checked state machine for no gain.

**2. Why detect the wall without the model?**
The model proposes; something deterministic decides. A password field is observable, and the cost of a model guessing wrong is an invented account.

**3. Why hide the frame during screenshots?**
Screenshots feed the vision model and the stored record. A coloured border would be pixels it could mistake for page content.
