# B38 - Free-tier quotas, request pacing and model rotation

## What was built

The agent now survives the free tiers it is actually run on. Gemini models rotate when one is used up, requests are paced under a per-minute limit, a short rate limit is waited for, and network errors retry and fall back.

## Key decisions

Every "rate limiting" error traced back to one number: the free tier allows 20 requests a day per model, and a task spends 3 to 5. No amount of retrying fixes a daily quota, so the work was to use more buckets (other models have their own) and to stop wasting requests: pacing avoids the per-minute 429, a used-up model is remembered, and a wait longer than 90 seconds fails fast. A real run also showed grounding overriding a valid planner choice with an unnamed widget input, so the planner's input check now applies to grounding too.

## Viva questions

**1. Why rotate models instead of switching provider?**
Quotas are per model, so another model on the same provider and key has its own allowance and the same API, without a second set of limits to hit.

**2. Why pace requests rather than catch the 429?**
A 429 costs a failed call and usually lands the next one on a provider with limits of its own. Waiting a few seconds for a turn costs only the wait.

**3. Why must a check that refuses a planner choice also bind grounding?**
Otherwise the guarantee has a hole: a later stage can undo what the earlier one enforced. The same check runs on both so neither can pick a field the other would have refused.
