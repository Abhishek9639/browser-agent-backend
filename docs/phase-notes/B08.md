# B08 - Playwright driver and action executor

## What was built

The layer that actually touches a browser, and the typed vocabulary it accepts.

- `app/agent/browser/actions.py` - one model per allow-listed action.
- `app/agent/browser/errors.py` - the error codes everything above the driver speaks.
- `app/agent/browser/driver.py` - `BrowserDriver` protocol and `PlaywrightDriver`.
- `tests/fixtures/html/` plus a local server fixture.
- 96 unit tests; `make check` runs them all.

## Key decisions

**The union *is* the allow-list.** `Action` is a discriminated union of twelve models, so an invented action cannot be constructed at all, let alone executed. `parse_action` checks the name before building anything and raises `ActionNotAllowedError` rather than a validation error, because the two mean different things upstream: a bad field is worth one repair retry (spec section 4.5), an invented action never is.

**Actions are frozen and forbid extra fields.** Frozen because a `task_steps` row is a record of what ran, and a mutable action could desync the record from reality. `extra="forbid"` because a model emitting `targetIndex` when the field is `target_index` should fail loudly rather than silently doing nothing.

**Only http and https.** `file://` reads the host filesystem, `javascript:` executes in page context, and `data:` smuggles an entire document past the domain allow-list. All three are blocked at parse time, before the sandbox check even runs.

**The domain check parses the URL.** Substring matching would let `evil-localhost.test` through because the string contains `localhost`. `host_is_allowed` compares the parsed hostname, and treats a bare entry as "any port on that host" and a port-qualified entry as that port only. An empty list blocks everything: a misconfiguration must fail closed, not open.

**A sandbox breach is raised; a page problem is reported.** `DomainNotAllowedError` and `ActionNotAllowedError` propagate, because retrying them is pointless and executing them would be unsafe. Everything else, a missing element, a timeout, a disabled control, comes back as `ActionResult(ok=False)` with one of our codes, because those are exactly what the recovery ladder exists to work around.

**Redirects are re-checked.** `_navigate` validates the requested URL, then validates `page.url` again after the load. A redirect is the obvious way for a page to walk the agent out of its sandbox, and the plan cannot be trusted about where it ended up.

**Locale and timezone are pinned, not inherited.** `en-IN` and `Asia/Kolkata` mean a run on a laptop and a run in CI see the same date order and currency formatting. For a flight-booking demo that is the difference between `20/10` and `10/20`.

**Error messages are trimmed to one line and 200 characters.** Playwright dumps page snippets into its exceptions, and spec section 10 forbids storing page content.

## Three bugs the tests caught

**Phantom tabs.** `context.new_page()` also fires the context's `page` event, so every tab we opened ourselves was counted twice: the listener tracked it, then `_track` tracked it again. A two-tab test saw three. `_track` is now idempotent, returning the existing id for a page it already knows.

**Scroll silently did nothing.** `page.mouse.wheel` requires the pointer to be over the scrollable area and is a no-op otherwise, which headless it always was. `scroll_y` stayed at zero while the action reported success, which is the worst kind of failure: the verifier would have seen "no change" and blamed the page. Replaced with `window.scrollBy`, which is deterministic and still fires scroll events for infinite-scroll pages.

**A test that proved nothing.** The first `test_downloads_are_refused` asserted the context was not `None`, which would pass with downloads fully enabled. It now clicks a real download link and asserts nothing completes. Flipping `accept_downloads` to `True` in the driver makes it fail, which is the check worth having.

## Viva questions

**Why is `BrowserDriver` a Protocol rather than a base class?**

So the orchestrator can be tested without a browser. The loop in spec section 4.2 is the most intricate code in the project, and testing it against real Chromium would make every test slow, flaky and dependent on page timing. A protocol lets a fake driver return scripted `ActionResult`s, so the agent evaluation suite in section 11, labelled page-state in, expected action out, runs in milliseconds with no browser at all. It also keeps the dependency pointing one way: the driver knows nothing about the orchestrator, and swapping Playwright for something else later touches one file.

**Why does a fresh BrowserContext per task matter, rather than a fresh page?**

A context is the isolation boundary: cookies, localStorage, sessionStorage, IndexedDB, cache and permissions all live in it. Pages within one context share all of that. If two tasks shared a context, a user who logged into a site in task A would still be logged in during task B, possibly another user's task, which is a cross-user session leak. Tests assert this directly for both cookies and localStorage. The cost is that each task pays context startup, which is milliseconds, against a browser launch which is far more; that is why the `Browser` can be shared across tasks while the context never is.

**The driver catches every Playwright exception. Is that not hiding failures?**

It is translating them, not hiding them. Each one becomes an `ActionResult` with a code, a one-line message and the before and after URLs, all of which get persisted on the step and streamed to the live view, so nothing is lost. What it prevents is Playwright's error model leaking upward: without it, the recovery ladder would be matching on Playwright message strings, and so would the orchestrator, and swapping the automation library would mean rewriting both. There is one deliberate gap: `UNKNOWN`. If that code ever appears it means the mapping missed a case, which is a bug in the driver rather than a page behaving badly, and a test asserts the common failures never map to it.

## Follow-ups

- `make check` now takes about 47 seconds rather than 2, because the browser tests run in it as the part specified. `uv run pytest tests/unit -m "not browser"` skips them for a fast loop.
- `click`, `type` and `select` take a selector string. Resolving the perception layer's element index to a selector is the next part's job.
- `capture_state` returns url, title, tabs and scroll position. The compact DOM summary from spec section 4.6 is separate and more expensive.
- The `Playwright` instance and `Browser` are per-driver unless one is injected. Sharing one browser across tasks belongs in the lifespan wiring.
